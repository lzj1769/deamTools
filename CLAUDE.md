# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

DeamTools is a Python command-line toolkit for deaminase-based chromatin accessibility analysis. In these assays a deaminase marks accessible chromatin by converting cytosine to uracil/thymine; the resulting single-base C→T (forward strand) / G→A (reverse strand) editing events are the accessibility signal. The toolkit covers the full path from raw reads to QC: deamination-aware alignment → per-base BigWig tracks / per-fragment tables → QC report (with a deaminase motif logo) → TF-motif matching.

The package root is `deamTools/` (note the capital T); the importable package is `deamtools` (lowercase) under `src/`. The outer directory also holds `data/` (sample BAMs/peaks/FASTAs, gitignored) and `test/` (ad-hoc shell scratch scripts, **not** the test suite).

## Commands

The project is managed with **uv**; `uv.lock` is committed and pins the whole dev
environment. Run everything through `uv run`, which syncs the venv first, so no
manual activation is needed.

```bash
# Set up (creates .venv from uv.lock) — run from deamTools/
uv sync --extra dev
uv sync --extra dev --extra seq2edit   # add torch for the seq2edit command

# Tests (pure-Python; addopts = -q, pythonpath = src)
uv run pytest
uv run pytest tests/test_qc.py          # single file
uv run pytest tests/test_qc.py::TestQC::test_edit_rate_and_opportunities  # single test

# Lint / format / types (config in pyproject.toml; line-length 88)
uv run ruff check src/ tests/
uv run black src/ tests/
uv run mypy src/

# Docs (Sphinx + MyST + sphinx_rtd_theme)
uv sync --extra docs
uv run sphinx-build -b html docs docs/_build/html   # CI uses -W (warnings = errors)
```

After editing dependencies in `pyproject.toml`, run `uv lock` and commit the
updated `uv.lock`; CI syncs with `--locked` and fails if the two disagree.

CI has two jobs. **Tests** runs pytest on 3.12 and 3.13; **Lint and type-check** runs
`ruff check src/ tests/`, `black --check src/ tests/` and `mypy src/` on 3.12, each as a
separate step with `if: '!cancelled()'` so one push reports every problem rather than one
per round trip. All four are clean as of 2026-09-10 — keep them that way rather than
letting a backlog build up again.

Tests synthesize BAM/FASTA/BigWig fixtures with `pysam`/`pyBigWig` in tmp dirs (see helpers like `_make_read`/`_write_bam` in `tests/test_bam2bw.py`). They do **not** require `bwa`/`samtools` on PATH; `motifmatchpy` is a hard dependency and is exercised directly (`tests/test_matching.py` builds motifs in memory). The `index`/`align` commands need `bwa`+`samtools` at runtime; `match` needs the optional `pyjaspar` for JASPAR fetch.

## Architecture

CLI entry point is `deamtools.cli.main:main` (also `python -m deamtools`). `cli/main.py` is a single argparse dispatcher: each subcommand has an `_add_*_parser` builder and an `_run_*` thunk that unpacks the namespace and calls the module's public `run_*` function. `_log_invocation` echoes resolved arguments MACS2-style at INFO. **All CLI surface lives in `cli/main.py`**; implementation modules expose only the `run_*` entry point plus private helpers.

| Command | Module | What it does |
|---|---|---|
| `index` | `align/index.py` | `run_index` — builds the doubly-converted BWA index (+ FASTA `.fai`) |
| `align` | `align/align.py` | `run_align` — converts reads, runs `bwa mem`, restores, sorts to BAM |
| `bam2bw` | `preprocessing/bam2bw.py` | `run_bam2bw` — per-base editing **count** or **ratio** BigWig |
| `bam2fragment` | `preprocessing/bam2fragment.py` | `run_bam2fragment` — per-fragment editing-signal table (bulk or barcoded) |
| `qc` | `qc/qc.py` | `run_qc` — QC metrics → JSON + self-contained HTML report (incl. motif logo) |
| `match` | `motif/match.py` | `run_motif_matching` — motifmatchpy motif scan → BED of binding sites |
| `footprint` | `footprint/footprint.py` | `run_footprint` — TF footprint score + permutation p-value at motif sites, from a BigWig |
| `seq2edit train` | `seq2edit/` | `run_train` — train a CNN (`EditNet`) mapping one-hot DNA → per-base editing rate (deaminase sequence bias), Poisson loss |
| — | `utils/` | `_load_regions` (BED parse+merge), `get_chrom_sizes_from_{bam,file}`, `iter_fragments`/`merge_fragment_bases`/`mates_can_pair` (`fragments.py` — mate pairing and overlap collapsing, shared by `bam2bw` and `qc`), `get_version`, `logger` |

`preprocessing/fragment2bw.py` is an empty placeholder (not wired up).

### Output-path convention

All commands that write output (`index`, `align`, `bam2bw`, `bam2fragment`, `qc`, `match`) take `--out_dir` + `--out_name` and write `<out_dir>/<out_name>.<ext>` (`.bam`/`.bw`/`.tsv`/`.json`+`.html`/`.bed`; `bam2fragment --gzip` adds `.gz`). For `index`/`align` these are optional/derived where noted (`index` defaults the converted-index location next to the FASTA; `align --index` points at a custom one). The FASTA `.fai` is always written next to the FASTA (the pysam-based commands require it there).

### The deamination-aware alignment scheme (index + align)

The conceptual core, spanning two files (bwa-meth / three-letter strategy):

- **`index`** writes a *doubly-converted* reference (`<...>.deamtools.c2t`): every chromosome appears twice — a C→T copy prefixed `f` and a G→A copy prefixed `r` — then `bwa index`es it.
- **`align`** uses a **dual-conversion, take-best** strategy (the ACCESS-ATAC deaminase edits both strands, so one read can carry both `C→T` and `G→A`). `_feed_converted` emits each read twice — single-end as `ct`/`ga` candidates, paired-end as two fragment orientations `f` = (R1 C→T, R2 G→A) and `r` = (R1 G→A, R2 C→T) — sharing the read name, with the original SEQ in `YS:Z:` and the candidate in `YC:Z:` (carried through `bwa mem -C`). **The two mates are not converted differently**: each candidate is one conversion applied to the whole fragment in *reference* space, and read 2's label flips only because its FASTQ sequence is the reverse complement — `revcomp(s.replace('G','A')) == revcomp(s).replace('C','T')`. That flip is what keeps both mates on the **same** converted contig (`f`→`f<chrom>`, `r`→`r<chrom>`) so bwa can pair them. **Do not add the other two combinations** (both mates `ct`, or both `ga`): a `ct` mate goes to `f<chrom>` and a `ga` mate to `r<chrom>`, so they split the pair across contigs — measured over 300 simulated fragments they keep the mates together only 7% of the time and yield **zero** proper pairs, while still scoring mean ΣAS ~177, *above* the valid `r` candidate's 159, so take-best would sometimes pick a non-pair over a correct pair. This was proposed once (2026-09-10) on the reading that `f = (R1 C→T, R2 G→A)` means the mates get different conversions; `docs/algorithm.md` now carries the diagram and the table. A feeder thread pumps the candidates into `bwa`'s stdin; the main thread groups bwa's output by read name (`_process_sam` relies on bwa preserving input order so a read's candidates are consecutive), keeps the higher-scoring candidate (`_primary_score` = sum of mates' `AS`), then `_restore_alignment` restores SEQ from `YS`, strips the `f`/`r` RNAME/RNEXT prefix, and drops `YS`/`YC`; `@HD`/`@SQ` are rebuilt from the FASTA `.fai`.

**Flow:** the restored SAM is written to `<out_dir>/<out_name>.sam`, then `samtools sort` converts it to a coordinate-sorted `<out_name>.bam` and it is indexed. (This is now a write-then-sort flow, not a single concurrent pipe; the `.sam` is left in place.)

### Signal computation conventions (shared across modules)

- **Edit definition.** `bam2bw` and `qc` count edits *strand-agnostically*: any reference `C→T` **or** `G→A` mismatch regardless of read orientation (see `_get_edit_count`; `qc._process_chrom`). `bam2fragment` calls the same two patterns but keeps them in **separate output columns** (`C→T` then `G→A`), so the edited strand survives into the table — the ACCESS-ATAC preprint names resolving both strands as a route to better allelic occupancy imputation, and `occupancy` is the command that will consume it. **Never gate an edit pattern on `read.is_reverse`.** `bam2fragment` did until 2026-09-10 (`C→T` on forward reads, `G→A` on reverse), which reads as if orientation told you which strand was deaminated. It does not: a BAM stores SEQ in reference orientation and library prep fixes the deaminated U into a real T:A pair both strands carry, so either pattern appears on either orientation. Measured on `data/ACCESS-ATAC/chr10.bam`, `is_reverse` predicts a read's dominant direction only ~65% of the time and the rule discarded **35.5% of editing events** — events with the same `TC` enzyme-motif fingerprint (39.0–39.1% TC in all four orientation x pattern cells) as the ones it kept, so genuine editing.
- **Fragment merging.** `bam2bw` and `qc` both count per **fragment**, not per record, through the shared `deamtools/utils/fragments.py`: `iter_fragments` groups records by read name (yielding orphans at the end so nothing is dropped) and `merge_fragment_bases` collapses a fragment's mates into `reference position -> base`, the higher base quality winning a disagreement and an **equal-quality** disagreement being dropped as ambiguous (quality scores are binned on modern instruments, so ties are common and "first mate wins" would just mean "read 1 wins"; it costs 0.0025% of positions on chr10). Mates overlap whenever the insert is under 2x the read length, and that overlap is the *middle* of the fragment, not a random subset of positions, so counting it twice biased every rate rather than just inflating totals: it was **24.5% of `qc`'s opportunities** and **21.2% of `bam2bw`'s count-mode signal** on `data/ACCESS-ATAC/chr10.bam`. The logic lives in one module on purpose — `qc` was fixed first (2026-09-10) and `bam2bw` was left per-record for several commits, which is exactly the drift to avoid. `bam2fragment` uses `merge_fragment_bases` too, but keeps its own pairing loop on purpose: it reports fragment *coordinates*, so it needs both mates and drops the pair when either fails `--min_mapq`, where `qc`/`bam2bw` keep a lone mate as a one-record fragment.
- **Read filtering.** Unmapped / duplicate / QC-fail / secondary / supplementary reads are always excluded, then `--min_mapq`; `--min_baseq` gates individual bases. Aligned positions come from `get_aligned_pairs(matches_only=True)`.
- **Parallelism.** `bam2bw`, `bam2fragment`, `qc` and `footprint` fan out over regions/chromosomes through `deamtools.utils.run_jobs`, which runs jobs in a **`ProcessPoolExecutor`** (changed from `ThreadPoolExecutor` on 2026-09-11). The per-read loops are pure Python, so threads were GIL-serialised: `qc --threads 12` on the 3.2 M-record concurrent ACCESS-ATAC BAM ran at 105% CPU in 192 s as threads, and takes 33 s at ~680% as processes. Three rules follow. (1) **Jobs and results must pickle**: pass jobs as `functools.partial` over *module-level* functions, and never put a lambda in a result — `_Stats.context` used `defaultdict(lambda: [0, 0])`, which fails with `Can't get local object ... <lambda>` the moment a pool is used (it is `defaultdict(_zero_pair)` now). (2) `run_jobs` yields **in submission order, not completion order** — callers fold floats, and completion-order merging changed the last digit of `qc`'s mean edit rate between runs (1.4e-17); outputs are now bit-identical for any worker count, and `tests/test_parallel.py` checks that for all four commands. (3) If `__main__` cannot be re-imported by a spawned worker — the program came in on stdin (`python -`, a heredoc), where Python records its path as the literal `<stdin>` — every worker dies with `FileNotFoundError: .../<stdin>` and the caller sees `BrokenProcessPool`; `_workers_can_start` detects that up front and `run_jobs` falls back to in-process with a warning. Note this is how *this assistant's* heredoc test snippets run, so they silently go serial; time real parallel runs through the CLI or a script file. (4) With `--threads 1`, or a single job, `run_jobs` runs in-process: no spawn, no pickling, and it is the path most of the test suite takes — so anything that only breaks under a pool needs a test in `tests/test_parallel.py`, over a reference with more than one contig. Worker functions still **open their own** `pysam`/`pyBigWig` handles.
- **BigWig ordering.** `pyBigWig` requires entries in `(chrom, start, end)` order; `run_bam2bw` sorts regions by BAM-header chromosome order and emits only non-zero bases (`span=1`).
- **`bam2bw` modes.** The ratio denominator is now counted in the same pass as the numerator, over the same merged fragments, and honours `--min_mapq`; it used to come from pysam's `count_coverage`, which applies **no mapping-quality filter**, so ratio mode divided edits from MAPQ-passing reads by coverage that included reads the numerator had excluded (fixed 2026-09-10 along with the fragment merge). `count` writes raw edit counts and honors `--extend_size` (broadcasts each event into a `2*extend_size+1` window); `ratio` writes `edits / total_ACGT_coverage`, masks positions below `--min_coverage` to 0, and ignores `--extend_size`. `--normalize` (count mode only; warns and is ignored in `ratio`) scales every value by `--scale_factor / total` so the track sums to `--scale_factor` (default `1e6`); `total` is summed over the **processed regions after `--extend_size` broadcasting**, so with `--regions` it is not a genome-wide count. Because that total spans all regions, `run_bam2bw` holds every region's signal array in memory (the `results` dict) before writing — the one place memory scales with the region set rather than with a single region.
- **`qc`.** **Editing is counted per fragment, not per record** (changed 2026-09-10). `_process_chrom` buffers a mate until its partner arrives, then `_fragment_bases` merges them into `reference position -> base`, so a position both mates cover is *one* observation; a disagreement there is a sequencing error (library prep turns the deaminated C into a real T:A pair that both mates report), so the higher base quality wins. Orphans — unpaired, mate filtered out, mate on another contig — are flushed at the end of the pass as one-record fragments rather than dropped. This is not cosmetic: on `data/ACCESS-ATAC/chr10.bam` **24.5% of `total_opportunities` was mate overlap counted twice** (62.8M → 47.4M), and removing it moved `global_edit_rate` 0.0824 → 0.0856 — the overlap is not a random subset, so the double count was biasing the rate, not merely inflating counts. `_MAX_EDITS` went 50 → 100 because merged fragments overflow the old cap (0.04% of chr10 fragments exceed 50 edits; the busiest has 88). The `reads` block still counts records; the new `fragments` block reports the denominators the editing metrics actually use. **Library layout** is decided before the main pass by `_detect_layout`: paired-end if any of the first 10,000 records has flag `0x1`, else single-end (recorded as `library_layout`). For a single-end library `proper_pair`, `proper_pair_rate` and the whole `fragment_length` block — and its summary-figure panel — are **omitted, not zeroed**: a proper-pair rate of 0 reads as a mapping failure and 0 bp is not a length. Everything else is identical across layouts, since a single-end read is just a one-record fragment (verified on a read1-only copy of chr10.bam: 5.35 edits/fragment, matching the old per-read figure). `bam2bw` was brought onto the same footing immediately afterwards.
- **`qc` subsampling.** `--n_reads` subsamples: the fraction is `n_reads / total` with the total taken from the BAM index (no extra scan). The unit of the draw is the **fragment**, keyed on `query_name` through `hashlib.blake2b` (`_keep_fragment`), so both mates always share its fate — drawing records independently would leave most kept fragments with only one mate and halve every per-fragment edit count (`test_subsampling_keeps_both_mates_or_neither`). blake2b rather than the builtin `hash()`, which is salted per process and would break reruns. The coin is flipped **before the read is examined**, so the draw is blind to content — a read carrying no editing event is kept at exactly the same rate as one full of them. Do not add a content condition there; `test_draw_ignores_whether_a_read_carries_an_edit` pins it. (`edit_rate_per_fragment.n_fragments_with_editable_bases` *is* conditional — on covering a reference C or G, not on being edited — and was called `n_reads` until 2026-09-10, which read as if the subsample required an edit. Keep the two names distinct.) Rates stay unbiased; reported counts are counts *of the sample*, and `metrics["sampling"]` records the fraction. TSS enrichment is deliberately not subsampled. Single pass over the BAM accumulates: read stats, editing rate, per-fragment edit-rate distribution, trinucleotide context bias, fragment-length distribution, optional TSS enrichment, and a **deaminase motif PWM** (window around each edit, centre excluded, G-edits reverse-complemented). **TSS enrichment** follows the **ENCODE ATAC-seq pipeline** (`encode_task_tss_enrich.py`): insertion 5' ends (`reference_start` forward, `reference_end - 1` reverse) binned at `_TSS_BIN = 10` bp over `±tss_flank` (2 kb), minus-strand TSS flipped so upstream is always left, averaged over TSS, divided by the mean of the two edge means over the outermost `_TSS_EDGE = 100` bp (the Greenleaf normalisation), and the score is the **peak** of that normalised profile — not an average over the centre, which is what this used to compute. The one deliberate deviation: ENCODE reaches the cut site through metaseq read *coverage* shifted by `-read_len/2`, which smears each insertion over a read-length box; `_tss_enrichment` counts the 1-bp cut site directly, so scores run slightly above ENCODE's, more so for longer reads. `_tss_sites` reads strand from BED column 6, falling back to column 4 for the common four-column `chrom start end strand` TSS files (`data/bap/bap/anno/TSS/` are that shape, and use `1`-style contig names that need a `chr` prefix for these BAMs). Sanity check: `data/ACCESS-ATAC/chr10.bam` scores **10.72** over 1,469 chr10 TSS. Outputs JSON + a self-contained HTML report that embeds a matplotlib summary figure, a dedicated TSS-enrichment plot with the score marked on it, and a `logomaker` motif logo (all base64, `Agg` backend). **Every plotted distribution has a companion CSV and is not duplicated in the JSON**, which names the file instead: `<out_name>.tss_enrichment.csv` (`position,insertions,mean_insertions_per_tss,normalized`; JSON `tss_enrichment.profile_csv`), `<out_name>.edits_per_fragment.csv` (`edits,fragments,fraction,is_overflow`, last row the ≥`_MAX_EDITS` overflow bin; JSON `editing.edits_per_fragment_csv`) and `<out_name>.edit_rate_per_fragment.csv` (`bin_start,bin_end,fragments,fraction`; JSON `edit_rate_per_fragment.histogram_csv` — the `histogram`/`bin_edges` arrays moved out of the JSON on 2026-09-11). The CSVs are written even with `--no_plot`. Keep new plots to this pattern: one CSV per plotted distribution, named `_csv_name(out_name, kind)`. The report header is a provenance table (sample, layout, BAM/FASTA/TSS paths, deamtools version, time). The motif logo's counts go to `<out_name>.motif_pfm.csv` (`position,A,C,G,T`, JSON `motif.pfm_csv`); its **centre row is filled in as `C = n_events`** — the accumulated PWM skips the edited base, but it is always C in the unified orientation — so the frequency logo can put the target C at position 0. `--logo_scale frequency|bits` picks the y axis, **default `frequency`** (since 2026-09-11; bits letters are barely legible when the flanks stay under ~0.15 bits): bits keeps the centre out (else its 2 bits flatten flanks that stay under ~0.15); frequency follows the maintainer's figure code (`figsize=(4, 2.5)`, 0–1 axis, `classic` colours, left/bottom spines at 0.8). The per-fragment edit-rate histogram is `_RATE_BINS = 200` equal bins over `[0, 1]` (that length is also the row count of `<out_name>.edit_rate_per_fragment.csv`) and is drawn on a **symlog** x axis with `linthresh=0.01` and ticks `0, 0.01, 0.1, 1`: real data piles up below 0.1, so a linear axis with coarser bins compressed the whole distribution into a few bars at the left edge. Both halves are needed — a log axis over 50 bins just turns the first bin into one slab.
- **`match`.** Builds a `motifmatchpy.MotifScanner` (`prepare_scanner`: log-odds matrices, p-value thresholds, `both_strands=True`), scans each region's sequence, and writes 6-column BED (`chrom start end motif score strand`). Motifs come from `--motif_files` (`.pfm`/`.adm`, read by `load_motifs_from_files`, named after the file stem), a caller-supplied list, or JASPAR (`pyjaspar`), in that precedence order. `_to_motif` passes an `mm.Motif` through unchanged and converts anything else from JASPAR-style `.counts`, so both motif sources share one scanner path. Replaced MOODS on 2026-09-10; hits are byte-identical (same log-odds construction, same forward-strand coordinates), and the scanner now returns each hit's motif name, end coordinate and strand directly, so `scan_sequence` no longer takes the motif list. **motifmatchpy is numba-JIT'd**: the first `scan` call costs ~4 s of compilation, after which it is marginally faster than MOODS. Do not benchmark it without a warm-up call.
- **`footprint`.** For each motif site (width `L`) reads a per-base BigWig over `[start-L, end+L)` and scores `mean(left flank) + mean(right flank) - mean(centre)`; a positive score gets a permutation p-value from `n_shuffles` within-window shuffles (vectorised with a NumPy `Generator`). Parses the regions BED directly (not `_load_regions`, which merges and drops names) and parallelises over chromosomes. Writes `chrom start end name fp_score p_value`.
- **`seq2edit`.** The one **nested** subcommand group (`deamtools seq2edit <train|…>`, `required=True` subparser) and the one feature needing the **optional** `torch` extra (`pip install 'deamtools[seq2edit]'`). `model.py` holds both the torch-free encoding/data-prep helpers (`one_hot_encode`, window tiling, `build_dataset`, conv-size math `flatten_dim`) and `EditNet`; importing `model.py` pulls in torch (for `EditNet`), so `train.py` keeps its top-level imports torch-free and defers `EditNet`/`build_dataset`/`dataset` imports inside `run_train` (via `_require_torch`, which raises an actionable hint) — importing the CLI therefore never pulls in torch. `train` tiles `--train_regions` into `--seq_len` windows (input = one-hot ref sequence, target = per-base `--bigwig` signal, treated as Poisson counts), trains `EditNet` (2 conv blocks → FC head → per-base **Softplus** rate λ) with a **Poisson NLL** loss (`PoissonNLLLoss(log_input=False)`) + Adam + `ReduceLROnPlateau` (ACCESS-ATAC defaults), and writes the best-validation checkpoint `<out_name>.pth` (state dict + rebuild `config` + loss history). `EditNet` mirrors ACCESS-ATAC's `cnn_bias_model` but computes the FC input size from the architecture (`flatten_dim`) instead of hard-coding `928`, and uses a Softplus rate head + Poisson loss instead of the reference's ReLU + MSE. `model.py` imports torch, so `tests/test_seq2edit.py` gates the whole file with `pytest.importorskip("torch")`.

The counting/alignment logic intentionally mirrors the upstream ACCESS-ATAC reference (pinellolab/ACCESS-ATAC); preserve that correspondence.

## Conventions

- Python ≥ 3.12; every module uses `from __future__ import annotations`. Type hints expected but `disallow_untyped_defs = false`.
- A leading underscore marks a package-private symbol (e.g. `_load_regions`, `_get_edit_count`); some are imported across modules within the package, so treat them as package-internal rather than file-private.
- New public functions follow the existing NumPy-style docstring convention (see `bam2bw.py` / `qc.py`).
- `version.py` resolves the version via `importlib.metadata`; the canonical version lives in `pyproject.toml`.
- Docs are **Sphinx** (`docs/conf.py`, MyST Markdown pages, `sphinx_rtd_theme`); the GitHub Actions `docs` workflow builds them and publishes `docs/_build/html` to the `gh-pages` branch.
